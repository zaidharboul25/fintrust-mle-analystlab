## 1. Purpose & Architectural Boundary

The objective of the Machine Learning Engineering (MLE) track is to establish a reliable, modular, reproducible, and integration-ready serving system. **The Data Science track owns model experimentation, hyperparameter tuning, and final predictive performance.** 

To prevent tight coupling between the operational pipeline and specific model algorithms (such as Logistic Regression), this document defines the formal **Model Integration Interface Contract**. 

Any model artifact meeting this specification—whether Logistic Regression, LightGBM, XGBoost, Random Forest, or a custom scikit-learn compatible estimator—can be seamlessly integrated into FinTrust without requiring code modifications to the data validation, preprocessing, API serving, or output persistence layers.

## 2. Model Artifact Specification

Model artifacts must be packaged and serialized using `joblib` as a Python dictionary bundle:

```python
artifact_bundle = {
    "model": estimator_object,               # Fitted model / pipeline
    "feature_names": list_of_feature_names,  # Exact list of features in training order
    "model_version": "ds_candidate_v1",      # Unique semantic version tag
    "target_mapping": {1: "Yes", 0: "No"},   # Mapping of class 1/0 to decision string
    "sanity_metrics": {                      # Validation metrics on test split
        "accuracy": 0.8210,
        "precision": 0.3540,
        "recall": 0.6520,
        "f1_score": 0.4580,
        "roc_auc": 0.7890
    },
    "trained_timestamp": "2026-10-01T12:00:00Z",  # ISO 8601 UTC timestamp
    "train_samples": 9600,
    "test_samples": 2400,
    "split_ratio": "80/20 (stratified)"
}
```

### Required Fields & Validation Criteria

| Field | Type | Requirement | Description |
| :--- | :--- | :--- | :--- |
| `model` | Python Object | **MANDATORY** | Must implement `.predict(X)` returning array of integer classes (0 or 1). Should implement `.predict_proba(X)` returning continuous probabilities. |
| `feature_names` | `List[str]` | **MANDATORY** | Non-empty list of string column names expected by `model` in exact column index order. |
| `model_version` | `str` | **MANDATORY** | Non-empty version identifier (e.g. `baseline_v1`, `xgb_v2.1`). |
| `target_mapping` | `Dict[int, str]` | Optional | Maps positive class 1 to `'Yes'` and negative class 0 to `'No'`. Default is `{1: 'Yes', 0: 'No'}`. |
| `sanity_metrics` | `Dict[str, float]`| Optional | Key evaluation metrics recorded during offline evaluation. |
| `trained_timestamp` | `str` | Optional | ISO 8601 UTC timestamp when artifact was generated. |

Artifacts that fail these criteria will be rejected with `ModelInterfaceError` upon load.

## 3. Preprocessing & Feature Schema Assumptions

1. **Feature Input Matrix**:
   - The model expects the exact set of features generated by `src.preprocessing.DataPreprocessor`.
   - Feature count is dynamic based on categorical levels (currently 57 features: 8 numerical/temporal + 49 one-hot categorical indicators).
2. **Missingness Policy**:
   - Upstream preprocessing guarantees zero missing values in all features passed to the model.
   - Categorical missingness (`Device_Type`, `Location`) is imputed as `'Unknown'` or customer `City`.
   - Numerical missingness is strictly disallowed by validation gating.
3. **Column Order Invariance**:
   - The `ModelInterface` automatically validates and aligns column order to `feature_names` prior to calling `.predict()` or `.predict_proba()`. Extra columns (e.g. `Transaction_ID`, `Customer_ID`) are ignored; missing columns raise an immediate, informative error.

## 4. Serving & Prediction Protocol

The ML Engineering pipeline interacts with models exclusively through the `ModelInterface` protocol:

```python
from src.model_loader import load_model

# 1. Load and validate artifact
model_interface = load_model("models/baseline_v1.joblib")

# 2. Inspect metadata
print(f"Loaded: {model_interface.model_version}")
print(f"Features expected: {len(model_interface.feature_names)}")

# 3. Compute continuous risk confidence (0.0 to 1.0)
confidences = model_interface.predict_proba(features_df)

# 4. Generate structured decisions
classes, confidences, decisions = model_interface.predict(features_df, threshold=0.50)
```

## 5. Step-by-Step Guide for Data Science Hand-off

When the Data Science track is ready to release a candidate model to replace the baseline:

1. **Train Model on Processed Data**:
   - Ingest `data/processed/FinTrust_Modelling_Ready.csv`.
   - Separate `X` (all columns except `Transaction_ID`, `Customer_ID`, `Risk_Review_Flag`) and `y` (`Risk_Review_Flag`).
2. **Preserve Feature Names**:
   - Capture `feature_names = list(X.columns)`.
3. **Bundle Artifact**:
   - Construct the dictionary bundle containing `model`, `feature_names`, and `model_version` (e.g. `ds_lgbm_v1`).
4. **Serialize via Joblib**:
   - Save to `models/<model_version>.joblib`.
5. **Verify Hand-off**:
   - Run the automated model loading test:
     ```powershell
     python -m pytest tests/test_model_loading.py -v
     ```
6. **Activate in Pipeline / API**:
   - Update `DEFAULT_MODEL_VERSION` in `src/config.py` or specify `--model-version ds_lgbm_v1` when invoking `src/prediction.py` or launching `src/api.py`.
